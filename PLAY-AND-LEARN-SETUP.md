# GraceGuide — going live (web v9 shell, Android 1.2.0)

Three things have to happen in Firebase before everything works for real
users. Do them in this order.

## 1. Add the new blocks to your live database rules (required)

Open Firebase Console → Realtime Database → **Rules**, and paste these blocks
**inside** your existing `"rules": { … }`, next to `"users"`, `"spacePosts"`
and the others. Do not replace anything that is already there.

| File (next to this one) | Block | What stops working without it |
|---|---|---|
| `games.rules.json` | `"games": { … }` | All multiplayer: rooms, invites, XP, leaderboards, Daily Challenge, "My games". (Solo still works.) |
| `community.rules.json` | `"publicProfiles": { … }` | Community → Users shows "Couldn't load people". |

If you added the earlier `"games"` block already, **replace it** with the new
one — it changed (rooms kept 3 days, AI questions, "My games").

Also check that your `"users"` rules let an account write its own
`users/{uid}/devotionStreak` and `users/{uid}/profile/faith` (they do if a user
can already write their own `users/{uid}` data, which notes and bookmarks need).

Do **not** publish `database.rules.json` from this folder: it is not your live
ruleset and would break Chats, Shepherd and the Bible.

If the top of your live rules has a blanket `".read": true` / `".write": true`
(or `"auth != null"`) at the root, these rules cannot restrict anything,
because in Firebase a rule that allows access higher up always wins. In that
case paste the live rules to me — they need tightening first.

## 2. Deploy the Cloud Functions (recommended)

Needs the Blaze plan and the Firebase CLI. From the `graceguide` folder:

```bash
firebase deploy --only functions
```

- **Invitation pushes** to phones in the background / closed apps.
- **The game referee** (`functions/games.js`): re-scores every finished game
  and becomes the only thing that can write XP, wins, streaks and badges. It
  also sweeps rooms older than three days.

## 3. Publish

- Web: upload the `graceguide` folder. `sw.js` is at cache version v9.
- Android: `graceguide-android/app/build/outputs/bundle/release/app-release.aab`
  or `…/apk/release/app-release.apk` — version 1.2.0 (code 3). Set the admin
  page's "Android latest version" to 1.2.0.
- Release web and Android together: games now carry AI-written questions, and a
  phone still on 1.1.0 cannot show those in a shared room.

## Community → Users: existing members

People appear in the Users list once they open the updated app (it writes
their public card: name, photo, short bio, joined, last active — never an
email). To list everyone straight away, sign in on the **web** app with an
admin account and open Community → Users once: it fills in the missing cards
from the admin directory.

## AI-written game questions — how accuracy is protected

Hosts pick Easy / Medium / Hard on a game's page. Questions are written by
the AI in the background and only reach players after all of this:

1. the engine's shape checks (four distinct options, a five-letter word, …);
2. the reference must be one real verse;
3. that verse is fetched from the Bible service (KJV) and checked by code — a
   Wordle word must be in it, a "this is in the Bible" quote must match it, a
   "not in the Bible" saying must not;
4. a second, strict AI pass sees each question beside the real verse text and
   must approve it;
5. the verse shown to players is the real verse text, not the AI's wording.

Anything that fails is dropped, and whenever verified questions aren't ready
(or the AI / Bible service is down) the built-in bank of 252 questions is
used. The bank is never removed. No automated check can make an AI infallible,
so please play a few Hard games yourself after release and tell me about any
question that looks wrong.

## What is where

| | |
|---|---|
| `js/games-core.js` | The engine: schedule, scoring, XP, badges, validation of custom questions. Shared by web, Android (Kotlin port) and the referee. |
| `js/games-bank.js` | The built-in questions. Generated — edit `graceguide-games-tests/bank-src.js`, run `node build-bank.js`. |
| `js/games-ai.js` | AI question writer + the checks above (Android: `games/GamesAi.kt`). |
| `js/games-net.js`, `js/games-play.js`, `js/games.js`, `css/games.css` | Rooms / the question screen / the Play & Learn pages. |
| `js/streaks.js` | Devotion streak + Faithfulness score and its ten titles (Android: `data/Faithfulness.kt`). |
| `games.rules.json`, `community.rules.json` | Rule blocks to merge (generated by `build-rules.js`). |
| `functions/games.js` | The referee. |
